五类对标图表的数据准备与统计缺口修复

工程版本 v0.0.11 · 2026-10-14 · 主归属 Observation & Evidence，横切 Contract/Identity 与 Presentation/Delivery。工具提供可审计观测事实及外部 Outcome 的阅读、聚合，不新增 Grader 或 Agent 执行器。

原始两份 v0.0.9 导出共有 306 条会话记录：WorkBuddy 137、Mobilework 41、TeleAgent 81、豆包 47。以下是对导出和当前代码的复核；旧分析文档中“聚合缺口已修正”指分析脚本的回退处理，不能作为采集器已修复的证明。

证据与修复

缺口复核与影响本次处理
缓存与实时数据混用导出指标、usage、events 可来自缓存，calls、failures 实时读取；采集窗口和规则版本可能不同。四个对象均出现指标与数组长度不一致，差异也可能包含粒度差异。导出所有明细实时只读，记录 bounded-read-window、每节读取状态和实际指标缺失清单。三家适配器复用同一份 calls/usage/failures。外部文件仍可能在读取过程中变化，不宣称原子快照。
流段被当 LLM 调用、重试被当成功Mobilework 对同一消息的 text/reasoning/tool-input 使用同一 ID，结束事件按消息 ID 查找首个 running；重试事件固定 status=ok。单看 running 比例不能证明模型不稳定。按消息、源 seq 和流段类型区分及配对；重试单独计事件，不伪造请求成功。流段结束不充当首 token。无法证明逻辑调用时 llm_call_count=null，另报流段观测记录。
工具名称大面积丢失旧导出 Mobilework 1,469/1,636 条、TeleAgent 3,228/3,319 条工具记录无名称；仅看 TOP 有名工具会严重少计。Mobilework 用 SQLite 标量投影避免长 JSON 解析截断，支持原生名称字段；TeleAgent 读取 $.tool、$.callID 和 $.state。未知名称保留 (unknown) 桶。
终态与率的分母TeleAgent 工具曾固定成功；多个适配器同时返回两个同名 success_rate，缓存中后者覆盖前者。工具率单独名为 tool_success_rate；已知结果率分母为 ok+error，取消及未知另报。冲突终态留 unknown。原始、去重、重复记录和终态覆盖分列。记录粒度不代表统一 attempt。
Token 口径WorkBuddy input 含 cache，TeleAgent 不含；Mobilework unknown。豆包 usage 未捕获。用 unknown 当 false 或将缓存、reasoning 再加一次会失真。保留原始分项，已知 cache 包含关系才算规范总量/净输入；供应商 reported_total 可直接保留。session 累计和 attempt 明细择一，不叠加；usage ID 去重。unknown cache 命中率=null。
归因和会话边界Mobilework 无会话绑定的进程日志可能计入每个会话；WorkBuddy trace_duration 可扫描到其他会话。未绑定进程日志留 installation scope，不计会话错误；Trace 明确核对 sessionId。诊断类别与调用失败独立，保留 overlapping incidence，不能解释为唯一根因。
成功与重复试次活动不能证明执行完成；无活动不能证明空跑失败。标题聚类会把不同任务合并；6/15/29 次不能直接按“五次”计算。活动代理与独立 Outcome 分列；任务成功率缺 Outcome=null。Task/Trial/Batch 仅显式绑定，恰好 k 个不同 trial ID、索引 1..k 且均有 Outcome 才算稳定性，缺/重/超试次整组排除。

入口与复现

Dashboard 顶部“图表数据”使用当前对象/日期筛选下载；完整与选中会话导出也包含 chart_data。GET /api/chart-data 与 GET/POST /api/export 共用采集链路。批量导出上限每对象 500 会话，元数据报告可能截断的对象。旧导出仍可离线准备，工具不改源文件、默认拒绝覆盖输出。

node scripts/prepare-chart-data.mjs --input tester-1=export-1.json --input tester-2=export-2.json --output chart-data.json
node scripts/prepare-chart-data.mjs --input tester-1=export-1.json --output bound-chart-data.json --manifest bindings.json --k 5

source_id 是操作员/采集部署命名空间。相同命名空间、对象、installation_id、session_id 的多次导出只取最新整份快照；不同测试员保留独立身份。未指定 source_id 时用文件 SHA-256，适合隔离未知来源；重复导出需要显式指定同一个来源。输出 sources 保留文件 SHA-256，不包含正文/个人路径。

{"bindings":[
  {"source_id":"tester-1","agent":"mobilework","session_id":"synthetic-noise","include":false},
  {"source_id":"tester-1","agent":"mobilework","session_id":"synthetic-session-1",
   "task_id":"synthetic-task","batch_id":"synthetic-batch","trial_id":"synthetic-trial-1","trial_index":1,
   "outcome":{"passed":true,"verifier":"independent-file-state","evidence_ref":"synthetic-receipt-1"}}
]}

例子完全合成；实际绑定必须匹配输入会话。默认不猜预热/系统记忆或标题编号；按 include:false 明确剔除，统计记录保留。Contract：绑定 Schema、图表数据 Schema。compare API 保留完整 metric_json；单位/语义混杂不聚合，partial 单列，已知结果率按 numerator/denominator 池化，百分比不求和。
